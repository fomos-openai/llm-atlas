# 05 推理、评测与服务

模型在训练结束后仍可通过推理时计算提高结果：更长思考、并行采样、搜索、工具和验证器都能增加成功率。这使能力成为按请求分配的动态预算，但也带来延迟与成本。可读思维链并不保证内部过程忠实，关键结论仍需外部证据或执行验证。

评测必须说明任务、提示、采样预算、上下文、工具权限、评审器和成本。公开基准容易污染与饱和，平均分会掩盖长尾。成熟 EvalOps 保存版本、置信区间、失败分类和发布门，并把生产事故转为回归测试。

## 把权重变成服务

推理系统使用 KV cache、连续批处理、量化、并行、投机解码和路由满足 SLA。首 token 延迟、每 token 延迟、吞吐、显存和成本相互制约。离线最高分模型未必是单位任务价值最优模型。

生产优化应基于真实输入/输出长度、并发和重试分布。任务成功一次的总成本，还应包含检索、工具、人工返工与失败影响。
