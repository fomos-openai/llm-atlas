# 06 上下文、RAG 与 Agent

上下文工程决定一次推理能看到什么：系统指令、用户请求、检索证据、记忆、工具结果和环境状态。它要求最小充分内容、来源隔离、明确优先级、过期检测和失败降级，而不是寻找一句万能提示词。

RAG 把动态或私有知识放入上下文。完整链路包含解析、分块、索引、查询改写、检索、重排、组装、生成和引用验证。引用存在不等于主张得到支持；检索召回与模型使用证据的能力需要分别评估。

## 从回答到行动

Agent 在观察、计划、调用工具、读取结果与验证之间形成闭环。工具 schema 只约束格式，不保证语义正确或授权合理。执行层需要参数校验、最小权限、幂等、审计和不可逆动作前的人工确认。

长时 Agent 还需要持久状态、检查点、预算、取消与恢复。多 Agent 只有在任务可分解、结果可合并时才值得引入，否则只会增加通信与相关错误。
